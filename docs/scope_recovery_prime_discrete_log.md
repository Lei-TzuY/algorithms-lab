# Scope recovery: bounded exact prime-field discrete logarithm

## Coverage decision

After exact planarity via rotation systems reached merged-main green, a fresh
live-code / PR-history / branch audit found no discrete-logarithm, baby-step
/ giant-step, or BSGS capability. The existing number-theory layer already
provides deterministic full-`uint64_t` primality and overflow-safe modular
multiplication/exponentiation, but it has no inverse-exponent search.

This slice deliberately leaves the recent graph-topology frontier and does not
touch the frozen compiler/backend excursion. `docs/scope_recovery_after_phase69.md`
remains the prospective governance authority.

## Production contract

`prime_discrete_log_bsgs(base, target, p, max_baby_steps)` solves

`base^x == target (mod p)`

for the **smallest non-negative** exponent `x` in the non-zero multiplicative
group of a prime field.

- `p` must be prime;
- `base` and `target` must both lie in `[1,p)`;
- a missing exponent returns `std::nullopt`;
- `target == 1`, `base == target`, and the degenerate `base == 1` cases are
  resolved without allocating a baby table;
- non-trivial search uses an explicit caller-visible `max_baby_steps` cap;
- if `ceil(sqrt(p-1))` exceeds that cap, the solver throws `std::length_error`
  rather than attempting an unbounded allocation.

The cap is a resource contract, not an approximation: every search that is
executed is exact over the complete exponent range `0 .. p-2`.

## Baby-step / giant-step invariant

Let `n = p-1` and `m = ceil(sqrt(n))`.

Production stores every baby step `base^j` for `0 <= j < m`, sorted by value and
then exponent. For giant block `i`, it computes

`gamma_i = target * base^(-i*m)`.

A baby hit `gamma_i = base^j` is equivalent to

`target = base^(i*m+j)`.

Giant blocks are visited in increasing `i`, and the sorted baby table returns the
smallest `j` for a repeated residue, so the first in-range hit is the smallest
non-negative exponent. Searching through `floor((n-1)/m)` covers every exponent
in `0 .. n-1`; if no hit exists, the target is outside the subgroup generated by
the base.

Because `p` is prime and `base != 0`, Fermat inversion supplies
`base^-1 = base^(p-2) mod p`. All modular products and powers reuse the sealed
full-width overflow-safe number-theory implementation.

The integer square root is computed by division-based binary search rather than
floating point, so the table-size decision is exact even near the `uint64_t`
limit.

## Verification

Focused candidate verification passes:

- GCC C++20 repository strict warnings-as-errors;
- Clang C++20 repository strict warnings-as-errors;
- actual GCC ASan+UBSan with leak detection.

Deterministic evidence covers invalid composite moduli, zero/out-of-range field
residues, zero resource cap, the prime-two group, trivial exponents, a known
primitive-root solution, a target outside the generated subgroup, explicit
resource-cap rejection, and a full-width prime whose trivial solution requires
no large table.

The primary differential oracle is deliberately independent of BSGS. For every
non-zero `(base,target)` pair over all 25 primes from 2 through 97, the test walks
powers from exponent zero upward using direct small-integer modular arithmetic
and records the first matching exponent. Production must return exactly that
value or exactly `std::nullopt`.

## Complexity and non-claims

For `m = ceil(sqrt(p-1))`, this direct sorted-table baseline uses `O(m)` resident
memory. Building/sorting the baby table is `O(m log m)` comparison work, and up
to `O(m)` giant probes each use `O(log m)` binary search plus overflow-safe
modular arithmetic. The public implementation therefore makes a conservative
`O(m log m * log p)` code-local arithmetic bound, or the conventional
`O(m log m)` bound under a fixed-word modular-arithmetic model.

No composite-modulus discrete logarithm, Pohlig-Hellman reduction, Pollard-rho
discrete log, cryptographic constant-time behavior, arbitrary-precision domain,
or practical attack on cryptographic-size groups is claimed. The explicit baby
step cap is part of the supported contract.
