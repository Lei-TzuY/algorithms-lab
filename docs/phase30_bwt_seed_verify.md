# Phase 30 — Exact Seed-and-Verify Bounded Edit-Distance Search

## Scope

Phase 30 adds an exact candidate-filtering architecture for byte-oriented bounded Levenshtein substring-start search. It does not replace or weaken the sealed Phase-27 BWT state-expansion solver. Instead it uses sealed exact BWT search for candidate generation and the sealed Phase-29 reconstruction substrate for exact candidate verification.

Production consumes a `BwtByteIndex`, a pattern, and edit budget `k`. It returns sorted exact start positions plus diagnostics for seed count, exact seed occurrences, unique candidate starts, candidates actually verified, dynamic-programming cells, and Phase-29 reconstruction LF steps.

## Completeness argument

For non-empty pattern length `m` and `k < m`, split the pattern into `k+1` non-overlapping non-empty contiguous seeds. The implementation distributes the remainder deterministically so the blocks cover the complete pattern without multiplication-overflow-prone endpoint arithmetic.

Consider any substring alignment with Levenshtein distance at most `k`.

- a substitution or deletion affects a pattern position in at most one seed;
- an insertion strictly inside a seed can disrupt at most that seed;
- an insertion at a seed boundary does not destroy either seed as an exact contiguous byte string;
- with at most `k` edit operations and `k+1` seeds, at least one seed is untouched and therefore occurs exactly in the matched text substring.

If that untouched seed begins at pattern offset `b` and its exact text occurrence begins at `q`, insertions/deletions before the seed shift `q` relative to the substring start by a net amount whose absolute value is at most `k`. Therefore the true substring start lies in the clipped interval `q - b ± k`. Phase 30 marks every start in that interval for every exact seed occurrence and deduplicates candidates before verification.

When no candidate is generated, the completeness argument itself proves that no match within budget exists; production can return without reconstructing the text.

## Exact verification

If at least one candidate exists, production calls `BwtByteIndex::reconstruct_text()` exactly once. No retained constructor-text copy is introduced.

For a candidate start `s`, any text substring within edit budget has length in `[m-k,m+k]`. A two-row Levenshtein dynamic program evaluates the pattern against every prefix up to the largest available admissible length in one pass; the final row is inspected over the complete admissible length interval. A candidate is returned iff at least one such exact DP value is at most `k`.

The fast-path semantics match sealed Phase 27: an empty pattern or `k >= m` matches every text boundary `0..n`, because deleting the complete pattern permits the empty substring at every boundary.

## Diagnostics and complexity boundary

Let `H` be the total number of exact seed occurrences and `C` the number of unique candidate starts. Seed lookup inherits the sealed exact BWT count/locate costs. Candidate marking costs the explicit clipped start bands generated by those hits and uses an `O(n)` byte bitmap.

If `C = 0`, Phase-29 reconstruction is skipped. Otherwise production performs one complete Phase-29 reconstruction, inheriting its `n` LF transitions and run-length occurrence access/rank costs. For candidate `s`, let `L_s = min(n-s,m+k)` with overflow-safe capping. Exact verification costs `O(m * L_s)` time and `O(L_s)` two-row workspace. The implementation exposes the actual DP-cell count rather than claiming a universal speedup.

This architecture can be substantially better than exponential state expansion when exact seeds are selective, but repetitive text or short seeds can produce `C = Theta(n)`. No universal faster-than-Phase-27, compressed-optimal extraction, heuristic-seed, or hidden polynomial-index guarantee is claimed.

## Verification

Deterministic cases cover empty/fast-path semantics, substitution, insertion, deletion, negative mathematical seed-center displacement near text start, repetitive candidate deduplication, absent-seed no-reconstruction behavior, arbitrary embedded NUL/high bytes, and varied locate sample rates.

A fixed-seed randomized direct differential corpus checks 1,200 arbitrary small text/pattern/budget triples against an independent direct substring Levenshtein oracle. A second 180-case bounded corpus cross-checks exact positions against both that direct oracle and the sealed Phase-27 bidirectional BWT state-expansion implementation.

Algorithm-focused pre-upload verification also exercised 5,000 random small cases under strict GCC, strict Clang, and real GCC ASan+UBSan on an earlier compatible BWT backend. Exact current-backend integration remains gated by the repository's three-job remote CI and subsequent merged-main CI.

## Phase boundary

Phase 30 is an architecture comparison, not another scoring variant: sealed Phase 27 performs exact edit-state expansion entirely inside the bidirectional BWT, while Phase 30 performs exact BWT seed filtering plus one exact text reconstruction and polynomial candidate verification. The two implementations share the result contract but have materially different cost surfaces and failure modes.
