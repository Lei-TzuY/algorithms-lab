# Phase 46 — liveness-pruned scalar SSA

## Scope and contract

Phase 46 keeps the sealed Phase-45 scalar event IR and SSA value/witness format,
but changes phi placement from minimal SSA to liveness-pruned SSA.

Two public operations are added:

- `analyze_ssa_liveness` returns deterministic block-entry and block-exit
  liveness for every scalar variable on the start-reachable CFG;
- `construct_pruned_ssa` materializes only live-in phi nodes and then applies the
  same version-stack renaming and predecessor-witness semantics as Phase 45.

The input domain is intentionally unchanged: the CFG must be directed, the entry
must be predecessor-free, block count must match the graph, variable ids must be
valid, and unreachable blocks may not carry input instructions. Parallel edges
are accepted but block-level predecessor/successor witnesses are deduplicated.
Edge weights are irrelevant.

## Liveness semantics

Within an instruction, uses occur before the optional definition, matching the
sealed SSA renaming order. For each reachable block and variable production first
computes:

- `upward_use`: a use before the first local definition;
- `defines`: whether the block contains any local definition.

The standard equations are

```
live_out[b] = union(live_in[s]) for reachable successors s
live_in[b]  = upward_use[b] union (live_out[b] - defines[b])
```

Production evaluates their least fixed point by reverse propagation from
upward-exposed uses. When block `b` becomes live-in for a variable, every unique
reachable predecessor becomes live-out; a predecessor that does not define the
variable becomes live-in and is propagated further. Each block is enqueued at
most once per variable.

Unreachable blocks remain explicitly outside the analysis with false live-in and
live-out bits.

## Pruned phi-placement invariant

Phi placement is not implemented as `construct_ssa(...)` followed by filtering.
For each variable the worklist starts with the implicit entry definition and all
reachable explicit definition blocks. For every processed definition site,
production visits the sealed Phase-44 dominance frontier.

A frontier candidate is materialized only when the variable is live-in there.
Only a materialized phi becomes a new definition site eligible for later frontier
propagation. Therefore a dead phi cannot create downstream placement work.

Every emitted pruned phi consequently satisfies both obligations:

1. it belongs to the dominance-frontier closure generated by actual definitions
   and previously materialized pruned phis;
2. its variable is live-in at the phi block.

The predecessor-free entry must never acquire a phi.

## Renaming and witness semantics

After placement, Phase 46 preserves the Phase-45 observable semantics:

- version 0 is the explicit entry value for every variable;
- phi results are allocated before block-local instructions;
- uses read the current version before the same instruction's definition;
- definitions allocate monotonically increasing checked `size_t` versions;
- reachable successor phis receive one incoming value per unique predecessor;
- dominator-tree traversal is iterative and deterministic;
- phi variables, dominator children, predecessor witnesses, and successor target
  processing have deterministic vertex/variable ordering.

The implementation is a separate pruned-SSA construction surface so the sealed
minimal-SSA API and behavior remain unchanged.

## Complexity boundary

Let `Q` be the number of variables and let `F` denote the resident dominance-
frontier payload of the sealed Phase-44 index.

- local use/definition extraction is linear in input variable events;
- reverse liveness propagation is `O(Q(V+E))` after reachable predecessor lists
  are built, because each live-in block is propagated at most once per variable;
- pruned placement is bounded by definition/phi worklist processing over the
  sealed frontier payload, conservatively `O(Q(V+F))` beyond frontier
  construction;
- renaming is linear in reachable CFG adjacency, input events, emitted phis, and
  phi incoming payload, plus deterministic list sorting.

Phase 46 inherits the conservative construction bounds of the sealed dominator
and dominance-frontier indexes. No optimized SSA-construction, sparse liveness,
or compiler-wide complexity claim is imported.

## Verification

Deterministic regressions cover:

- a dead diamond where minimal SSA emits a phi and pruned SSA removes it;
- a live diamond where the join phi is retained and feeds the join use;
- a loop with one live and one dead loop-carried variable, retaining only the
  live header phi;
- same-instruction use-before-definition and a local definition that kills
  block-entry liveness;
- the Phase-45 directed/input/reachability/variable validation boundary;
- repeated-construction determinism.

The randomized corpus uses 350 fixed-seed reachable DAGs with 1–9 blocks, 1–4
variables, parallel edges, arbitrary ignored weights, and randomized block-local
use/definition events.

Liveness is checked against an independent forward oracle: from each block entry
and variable it searches for a path to a use before encountering a definition.
This oracle does not use production reverse propagation.

Pruned SSA is checked against an independent topological reaching-definition
oracle. At a join, differing predecessor identities create an oracle phi only if
the independently computed variable is live-in. The suite maps production SSA
versions back to initial/phi/definition identities and compares the exact phi
set, every renamed use/definition, and every phi incoming predecessor/value.
This oracle does not use the production dominator tree, dominance frontier, or
phi worklist recurrence.

Focused GCC and Clang strict-warning syntax gates pass before upload. Full
repository GCC, Clang, and ASan+UBSan execution remains the authoritative remote
integration gate.

merged-main run `34381733038` completed successfully on GCC release, Clang
release, and GCC ASan+UBSan.

The sealed scope is liveness-pruned scalar SSA only. Semi-pruned SSA is a weaker
placement regime and is not promoted merely for catalog breadth. MemorySSA,
optimization passes, post-dominators/control dependence, register allocation,
and incremental CFG maintenance remain separate architectural hypotheses.

Phase 47 promotes the next executable boundary: out-of-SSA lowering. Phi results
must become predecessor-specific edge copies with explicit parallel-copy
semantics; critical edges must be split when an edge-local copy bundle cannot be
placed unambiguously, and cyclic copy bundles must be scheduled without
clobbering source values. The lowering must preserve the sealed SSA value
identity/reachability semantics and expose replayable provenance suitable for
independent semantic verification.
