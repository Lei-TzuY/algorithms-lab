# Scope recovery — bounded exact Bareiss integer determinant

## Coverage decision

After the bounded-window LZ77 recovery, a fresh live code / pull-request / commit /
branch audit found no Bareiss, fraction-free integer determinant, or equivalent
exact integer-matrix determinant API in `algorithms-lab`. The existing Kirchhoff
spanning-tree slice does contain a determinant routine, but its contract is
explicitly Gaussian elimination over a prime field and returns a value modulo a
prime. This slice deliberately changes proof model again rather than extending
compression or adding another finite-field graph-counting helper.

The frozen Phase-45–69 compiler/backend surface and historically stale roadmap
frontier remain untouched under `docs/scope_recovery_after_phase69.md`.

## Production contract

`bareiss_determinant(matrix)` accepts a square matrix of signed 64-bit integers.

- the empty `0 x 0` determinant is `1`;
- `1 x 1` returns its only entry;
- deterministic pivoting chooses the first nonzero row at or below the current
  diagonal position and records row-swap parity;
- a missing pivot proves determinant zero;
- every Bareiss division after the first elimination stage must be exact;
- malformed non-square input is rejected.

The function is exact only inside an explicit **bounded arithmetic contract**:
every exact multiplication/subtraction numerator generated by Bareiss must be
representable by `int64_t`. Checked arithmetic throws `std::overflow_error`
before signed overflow. The implementation therefore makes no arbitrary-
precision claim and does not claim success merely because the final determinant
would fit in `int64_t`.

That distinction is executable: a matrix with two identical rows filled with
`INT64_MAX` has determinant zero, but its first Bareiss numerator requires a
product outside signed 64-bit range and is deliberately rejected.

## Fraction-free invariant

At elimination column `k`, let `p` be the chosen nonzero pivot and `d` the prior
pivot (`d = 1` for the first stage). Every trailing entry is updated as

`(a[i][j] * p - a[i][k] * a[k][j]) / d`.

Bareiss fraction-free elimination guarantees exact divisibility for exact
integer arithmetic. The implementation checks that divisibility instead of
assuming it. Row swaps change only determinant sign; the elimination state stays
integer. The final remaining diagonal entry, adjusted by swap parity, is the
matrix determinant.

## Verification

Focused candidate passes:

- GCC C++20 strict warnings-as-errors;
- Clang C++20 strict warnings-as-errors;
- actual GCC ASan+UBSan with leak detection.

Deterministic evidence covers empty/singleton matrices, a known `-306` example,
zero-leading pivots requiring row swaps, singular matrices, malformed shapes,
and bounded-overflow rejection including the final-zero/intermediate-overflow
case.

The primary randomized oracle is structurally independent of elimination. For
2,000 fixed-seed matrices of dimension `0..6` with coefficients in `[-5, 5]`,
tests enumerate every permutation and evaluate the Leibniz determinant formula.
Those bounds keep the oracle arithmetic itself comfortably inside `int64_t`.
The complete production result must equal that permutation expansion exactly.

## Complexity / non-claims

The direct dense implementation performs `O(n^3)` arithmetic slots and stores an
`O(n^2)` matrix copy. It does not claim arbitrary precision, modular
reconstruction, sparse determinant acceleration, asymptotically fast matrix
multiplication, Smith/Hermite normal form, inverse/solve functionality, or that
every matrix with an `int64_t`-representable final determinant is accepted.
